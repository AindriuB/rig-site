A task branch, from idea to done.

rig is a small command-line tool for the mechanical parts of a branch-per-task workflow: pushing a task branch, opening and reading pull requests, waiting for CI, keeping tasks, findings and notes, and printing where the work stands. It was built for loops where coding agents run these steps many times a day, but it does not depend on any particular loop.

What it prints

Real output from rig 0.5.0: push a task branch, wait for CI, move the task to done.

$ rig push 08
# rig 0.5.0, captured 2026-11-24
pushed task/08-demo to origin
$ rig pr wait 52
# rig 0.5.0, captured 2026-11-24
CI green: PR #52
$ rig task move 08-demo done
# rig 0.5.0, captured 2026-11-24
t-a70j  done

The narrow push

rig push takes a task id or a branch name and nothing else. It cannot push the default branch, a tag, a refspec or a force push, so it is safe to allow without a prompt.

✓ Accepted

  • rig push <task id>
  • rig push task/<name>
  • rig push record/<name>

A branch by task id or name that exists locally and is not the default branch. It goes to the branch of the same name on origin.

✕ Refused

  • Refused: the default branch
  • Refused: a tag
  • Refused: a refspec
  • Refused: a force push

There is no option for another remote, a force push or tags.

One interface over two forges

The same commands and the same output work on GitHub and GitLab. rig runs gh or glab underneath and uses the login you already have. It stores a token only for Jira, which has no such tool, and then in the OS keychain.

Where tasks live

Tasks, findings and notes live in your repository's git directory, outside any branch. They are in refs/rig/ and .git/rig/ of the clone, so they stay on your machine: rig does not push or fetch them.
